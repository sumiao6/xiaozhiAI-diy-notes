# 第六章　踩坑与排查手册

> 这一章不是"故事集"，是**查故障的手册**。遇到问题先按 6.1 的流程图定位，再查对应条目。
> 所有条目都来自本项目实际发生的问题，不是网上抄的。

---

## 6.1 先定位：问题出在哪一层

```
出问题了
│
├─ 编译就不通过？
│   └─ → 6.2 编译类（A1~A3）
│
├─ 编译通过但烧不进去？
│   └─ → 6.2 烧录类（A4~A6）
│
├─ 烧进去了但开不了机 / 一直重启？
│   └─ → 6.3 启动类（B1~B3）
│
├─ 能开机但某个外设不动？
│   ├─ 先看串口日志有没有该外设的 "ready" 那一行
│   │   ├─ 没有 → 6.4 硬件/接线类（C1~C5）
│   │   └─ 有   → 6.5 逻辑类（D1~D4）
│   └─ 再看是不是"部分能动"（能定位到具体通道/引脚）
│
└─ 小智听不懂 / 说没这个功能？
    └─ → 6.6 语音与工具类（E1~E3）
```

**判断"有没有 ready"的方法**：先打开串口日志（怎么看见 6.7，一句话：`idf.py -p COM口 monitor`），在里面搜这几个关键词

```
LedStrip:   彩灯板(light) on GPIO21 ...
Motor:      1号电机(motor1) IN-IN GPIO1/2 ...
Servo:      PCA9685 @0x40  SDA9/SCL10  11 路  50Hz(prescale 121) · 就绪
```

> 电机后面还会打印一行 `Car:` 开头的，那是把两个电机合起来的组控制器，跟"外设有没有起来"无关，跳过。

## 6.2 编译与烧录

### A1　`idf.py` 不是内部或外部命令

| | |
|---|---|
| **现象** | 命令行提示找不到 `idf.py` |
| **原因** | 没有激活 ESP-IDF 环境。ESP-IDF 装完不会自动加到 PATH |
| **解决** | 在 **PowerShell** 窗口里执行 `C:\Espressif\tools\Microsoft.v6.1.PowerShell_profile.ps1`（cmd 里不行） |
| **避免** | 每个新终端窗口都要激活一次。可以写个快捷方式放到桌面 |

### A2　VSCode 里所有 `#include` 标红

| | |
|---|---|
| **现象** | `<esp_log.h>`、`<driver/gpio.h>` 全红波浪线，但能正常编译 |
| **原因** | 微软 C/C++ 扩展默认只在**工程根目录**找 `compile_commands.json`，而 ESP-IDF 生成在 `build/` 下 |
| **解决** | 建 `.vscode/c_cpp_properties.json` 指定 `"compileCommands": "${workspaceFolder}/build/compile_commands.json"`，然后 `idf.py reconfigure` |
| **注意** | 改完要 `Ctrl+Shift+P` → `Developer: Reload Window`；首次索引 1~3 分钟，期间仍红是正常的 |
| **避免** | 别在 `settings.json` 里同时配 clangd 又没装 clangd 扩展，两套语言服务会打架 |

### A3　改了头文件但编译没生效

| | |
|---|---|
| **现象** | 明明改了 `config.h`，引脚还是老的 |
| **原因** | ① 改了另一份 `config.h`（工程里有几十个板型的同名文件）② 增量编译缓存 |
| **解决** | 确认改的是 `main/boards/bread-compact-wifi/config.h`；必要时 `idf.py fullclean` 后重编 |
| **避免** | 用 VSCode 的"转到定义"确认当前文件路径 |

### A4　烧录到一半掉线

| | |
|---|---|
| **现象** | `Writing at 0x... (51 %)` 之后报错退出 |
| **原因** | 波特率太高 + USB 线质量/接触不良 |
| **解决** | 波特率降到 **115200**：`idf.py -p COM15 -b 115200 flash` |
| **避免** | 别用又细又长的充电线，用带屏蔽的数据线 |

### A5　串口被占用，打不开

| | |
|---|---|
| **现象** | `Failed to connect to ESP32: Serial port is busy` |
| **原因** | 上一次的 `idf_monitor` 进程没退出，或 VSCode 的串口监视器还开着 |
| **解决** | 关掉监视器；任务管理器里结束残留的 python 进程 |
| **避免** | 退出 monitor 用 `Ctrl+]`，别直接关窗口 |

### A6　COM 口号突然变了

| | |
|---|---|
| **现象** | 昨天 COM13，今天插上变 COM15 |
| **原因** | USB 重新枚举。换 USB 口、换线、板子复位都可能触发 |
| **解决** | 设备管理器 → 端口，看当前是哪个 |
| **注意** | 如果连 **MAC 地址**都变了，说明你换了一块板子（本项目就遇到过：`cc:68:c7:80:31:30` → `84:c7:bb:7a:76:94`） |

## 6.3 启动类

### B1　板子无限重启，串口刷屏

| | |
|---|---|
| **现象** | 日志不停重复 `rst:0x3 (RTC_SW_SYS_RST)` 或 `Brownout detector was triggered` |
| **原因** | ① 供电不足（最常见）② 某处 `ESP_ERROR_CHECK` 失败 ③ 代码崩溃 |
| **解决** | 先拔掉舵机/灯板，只留主板看能否启动 → 能启动就是供电问题 |
| **避免** | 舵机电源独立；初始化失败的地方不要用 `ESP_ERROR_CHECK` |

**这条为什么排第一**：本项目 80% 的"莫名其妙重启"都是供电。

### B2　屏幕黑屏，但串口日志正常

| | |
|---|---|
| **现象** | 有 `SSD1306 driver installed`，屏幕不亮 |
| **原因** | ① SDA/SCL 接反 ② 地址不是 0x3C（有的是 0x3D）③ 对比度/供电 |
| **解决** | 交换 SDA/SCL 试；用 I2C 扫描确认地址 |
| **注意** | SSD1315 和 SSD1306 指令兼容，选 `CONFIG_OLED_SSD1306_128X64` 即可 |

### B3　只显示一半 / 花屏 / 镜像

| | |
|---|---|
| **现象** | 内容只在上半屏，或左右上下颠倒 |
| **原因** | 屏幕分辨率和配置不符，或镜像参数不对 |
| **解决** | 确认 `DISPLAY_HEIGHT`；调 `DISPLAY_MIRROR_X/Y` |

## 6.4 硬件与接线

### C1　某个电机完全不动

| | |
|---|---|
| **现象** | 1 号转，2 号不转；或两个都不转 |
| **原因** | ① **MRL298/L298N 的 ENA/ENB 跳线帽被拔了**（本项目真实踩过，完整经过见 [04 章 4.2](04-直流电机与差速控制.md)）② ZK-BM1 的话多半是某个 IN 脚没接对 ③ 该 GPIO 实际不通 ④ 电机线松 |
| **解决** | 先看跳线帽（有的话）；ZK-BM1 核对 IN1~IN4；再把该电机直接接电池，确认电机本身是好的 |
| **定位技巧** | 让电机"反转"，如果反转能转、正转不能，说明是**那一路 IN 脚**有问题（因为两路用的是不同引脚） |
| **避免** | 杜邦线接好后用手轻推每个插头，接触不良很常见 |

### C2　两个电机都转但整体原地打转

| | |
|---|---|
| **现象** | 说“前进”，整体在原地转圈 |
| **原因** | 左右轮镜像安装，同一信号到两侧方向相反 |
| **解决** | 把一侧的 `MOTOR_INVERT` 改成 1 |

### C3　舵机全部乱抖 / 主板一碰舵机就重启

| | |
|---|---|
| **现象** | 舵机抽搐，或动作瞬间板子复位 |
| **原因** | ① 没共地 ② 舵机电源取自主板 3V3 ③ 舵机那组干电池快没电了 |
| **解决** | 换 4 节新干电池（或 5V/8A 开关电源）+ 共地；PCA9685 的 VCC 接 3V3、VIN 接独立电源 |
| **数据** | 满配 8×MG90S 理论上限约 5.6A（本项目 4 个舵机实测没重启过）。舵机那组电池不要跟主板共用一路，否则舵机一动就把主板拉重启。总账见 [01 章 1.9](01-环境与接线.md) |

### C4　灯板颜色不对 / 只亮第一颗

| | |
|---|---|
| **现象** | 说"红色"显示绿色；或只有第一颗亮 |
| **原因** | ① 颜色顺序是 RGB 不是 GRB ② 实际灯珠数和 `LED_STRIP_COUNT` 不一致 |
| **解决** | 构造参数 `grb_order` 改 `false`；改 `LED_STRIP_COUNT` |

### C5　超声波及 5V 传感器（预警）

| | |
|---|---|
| **现象** | 还没接，但接之前必须知道 |
| **原因** | HC-SR04 的 **Echo 输出是 5V**，ESP32-S3 GPIO 绝对最大 3.6V |
| **解决** | `Echo —[1kΩ]—+—[2kΩ]— GND`，中间点接 GPIO（约 3.33V） |
| **注意** | 直连是**渐进性损坏**，可能当场没事，几天后那个脚就死了 |

## 6.5 逻辑类

### D1　语音说"开灯"，灯闪一下就灭

| | |
|---|---|
| **现象** | 有反应但立刻复原 |
| **原因** | 回调里改了状态，但渲染任务读的是另一份变量（没有 `volatile` 或作用域写错） |
| **解决** | 确认状态变量是成员变量且带 `volatile` |

### D2　一次语音指令，硬件动作重复多次

| | |
|---|---|
| **现象** | 说一次"闪一下"，闪了三次 |
| **原因** | 模型把一句话拆成多次工具调用；或回调里循环写 |
| **解决** | 回调只做一次状态变更，动画交给渲染任务 |

### D3　特效跑几十分钟后错乱

| | |
|---|---|
| **现象** | 流水灯突然倒着跑、颜色乱跳 |
| **原因** | 用 `int` 帧计数器累加毫秒，约 24.8 天溢出（本项目早期版本） |
| **解决** | 改用 `esp_timer_get_time()`，永远不溢出 |

### D4　调 `led_strip_clear()` 灯不灭

| | |
|---|---|
| **原因** | `clear` 只清内存缓冲区，不发送 |
| **解决** | 紧跟 `led_strip_refresh(strip_)` |

## 6.6 语音与工具

### E1　小智说 `the number of tools has reached limit: 32`

| | |
|---|---|
| **现象** | 语音报错，新加的功能用不了，但旧功能正常 |
| **原因** | **服务端硬限 32 个工具**。本项目自建 19 + 系统 2 = 21，还剩 11 个名额（算法见 [2.7](02-代码结构与改动清单.md)） |
| **解决** | 合并工具（见第二章 2.7）：开关合成布尔参数、多对象共享一组工具 + id |
| **不能做什么** | 改 `mcp_server.cc` 没用，限制在服务端 |

### E2　小智说"我没有这个功能"

| | |
|---|---|
| **现象** | 工具明明注册了，模型说没有 |
| **原因** | ① 工具名重名被**丢弃**（串口有 `Tool ... already added` 的 W 级警告，但不报错）② 描述写得太含糊，模型不认为该用 |
| **解决** | 全局搜工具名确保唯一；在描述里把用户的**原话**列进去 |
| **例** | 不要写"控制灯"，要写"用户说'开灯''打开彩灯''亮起来'传 true" |

### E3　小智编造了一个不存在的设备

| | |
|---|---|
| **现象** | 从没设过舵机，它却说"7 号舵机已转到 180 度" |
| **原因** | **大模型幻觉**。它看到工具列表里有 `set_angle(id, angle)`，就自己编了个调用结果 |
| **解决** | 这是模型行为，不是固件 bug。可以做的是：让工具返回真实状态，并在系统提示里强调"不确定就查 get_status" |
| **教学价值** | 讲"AI 会一本正经地胡说"的最好案例 |

## 6.7 怎么读串口日志

### 日志等级

| 字母 | 等级 | 说明 |
|---|---|---|
| `E` | Error | 必须处理 |
| `W` | Warning | 可能有问题 |
| `I` | Info | 正常信息，本项目启动日志都是 I |
| `D` | Debug | 调试信息，默认不显示 |

### 本项目关键日志对照

| 日志片段 | 含义 | 没有它说明 |
|---|---|---|
| `Install SSD1306 driver` | 屏幕驱动加载 | 屏幕配置或 I2C 有问题 |
| `彩灯板(light) on GPIO21, 9 leds active` | 灯板初始化成功 | RMT 或引脚问题 |
| `1号电机(motor1) IN-IN GPIO1/2, LEDC ch7/6` | 电机通道分配成功 | 通道用尽或引脚非法 |
| `PCA9685 @0x40 ... 就绪` | 舵机板通信正常 | I2C 接线/地址/供电问题 |
| `通道 3 被重复占用` | 通道表写错了 | — |
| `LEDC 通道用尽（舵机太多）` | 电机分了 4 个通道后没了 | 减少电机或改方案 |

### 抓日志的正确姿势

```bash
idf.py -p COM15 monitor
```

- 退出：`Ctrl+]`
- 想保存到文件：`idf.py monitor` 是交互式终端，**用 `>` 重定向拿不到内容**。改用串口助手（SSCOM / PuTTY）打开同一个 COM 口、波特率 115200，开启"保存到文件"。注意一个串口同时只能被一个程序占用，先把 monitor 关掉
- 只想看某类：日志里直接 `Ctrl+F` 搜 `E (` 找错误

## 6.8 一句话速查表

| 症状 | 最可能的原因 | 第一动作 |
|---|---|---|
| 板子不停重启 | 供电不足 | 拔掉舵机/灯板再试 |
| 电机不动 | ENA/ENB 跳线帽（MRL298）或 IN 脚（ZK-BM1） | 看板子 |
| 原地打转 | 镜像安装 | 改 `INVERT` |
| 舵机乱抖 | 没共地 | 量 GND 通断 |
| 灯不灭 | 少 refresh | 看代码 |
| 灯全白 | 没设颜色 | 加 `color` 参数 |
| 屏幕黑 | SDA/SCL 反了 | 交换试试 |
| 烧录掉线 | 波特率太高 | 降 115200 |
| 满屏红波浪线 | 找不到 compile_commands | 建 `c_cpp_properties.json` |
| 工具超限 | 32 上限 | 合并工具 |
| 小智编造设备 | 模型幻觉 | 不是 bug |
| 传感器读数乱跳 | 5V 直连 / 无分压 | 立刻断电加分压 |
